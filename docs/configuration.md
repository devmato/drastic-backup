# Configuration

dRastic configuration is environment-driven. Application defaults live in the backend and agent `config.py` modules. Values from the process environment use the `DRASTIC_` prefix and override those defaults.

Supported environments are `dev`, `test`, and `prod`. Generate local env files with:

```bash
./scripts/generate-env.sh dev
./scripts/generate-env.sh test
./scripts/generate-env.sh prod
```

## Required Production Values

| Variable | Purpose |
| --- | --- |
| `DRASTIC_APP_MASTER_SECRET` | Master secret used to derive Flask, JWT, and settings-encryption keys when explicit Flask/JWT secrets are not set. |
| `DRASTIC_SQLALCHEMY_DATABASE_URI` | MariaDB connection string for the backend. |
| `MARIADB_PASSWORD` | MariaDB user password; keep it in sync with the backend connection string. Use URL-safe characters (the generator uses random hex). |

## Environment Files

| File | Tracked | Purpose |
| --- | --- | --- |
| `.env.example` | yes | Server configuration template for Compose. |
| `.env` | no | Active server or agent-host configuration. |
| `.env.agent.example` | yes | Standalone Docker agent configuration template. |
| `.env.dev` | yes | Ready-to-run local development configuration. |
| `.env.dev.override` | no | Local developer-specific overrides generated by `./scripts/generate-env.sh dev`. |
| `.env.test.example` | yes | Test server configuration template. |

Compose loads `.env` into dRastic application containers through `env_file`. Values declared directly in a service's `environment` section take precedence. MariaDB and other third-party containers receive only their explicitly listed variables. The examples omit values that already have defaults; add an override to `.env` only when it differs. The generator does the same for production; test environments keep separate storage paths.

## Server Runtime

| Variable | Default | Purpose |
| --- | --- | --- |
| `DRASTIC_ENV` | `prod` | Active environment name. Development tooling sets `dev` explicitly. |
| `DRASTIC_SERVER_IMAGE` | `ghcr.io/devmato/drastic-backup-server:latest` | Server image used by production Compose; override to pin a release. |
| `DRASTIC_AGENT_IMAGE` | `ghcr.io/devmato/drastic-backup-agent:latest` | Agent image used by agent Compose and Docker install snippets; override on both hosts when pinning a release. |
| `DRASTIC_AGENT_GIT_REPOSITORY` | `https://github.com/devmato/drastic-backup.git` | Git repository used by the native pipe installer. Select its branch/tag/commit with installer `--ref`. |
| `DRASTIC_PUBLIC_URL` | empty | Canonical URL for agents and managed repository URLs. Without it, the UI uses the browser origin, but background-generated URLs fall back to `127.0.0.1`. Set it for remote agents. |
| `MARIADB_DATABASE`, `MARIADB_USER` | `drastic` | MariaDB database and user. If changed, update `DRASTIC_SQLALCHEMY_DATABASE_URI` too. |
| `TZ` | `UTC` | Container timezone for MariaDB and the rest-server; app containers use the host/image default unless set in their environment file. |
| `DRASTIC_BIND_BACKEND_PORT` | `5050` | Backend listen port inside the container. |
| `DRASTIC_HOST_BACKEND_ADDRESS` | `127.0.0.1` | Host address on which Compose publishes the backend. Use a specific private address only for a remote reverse proxy. |
| `DRASTIC_HOST_BACKEND_PORT` | `5050` | Host port exposed by Compose. |
| `DRASTIC_REST_SERVER_URL` | `http://rest-server:8000` | Internal rest-server URL used by the backend. |
| `DRASTIC_REST_SERVER_VERSION` | `0.13.0` | Explicit integrated rest-server container version. Review and change intentionally during upgrades. |
| `DRASTIC_DOCS_SITE_PATH` | `/app/docs-site` | Path to the built documentation site served under `/docs/`. |
| `DRASTIC_JWT_COOKIE_SECURE` | `false` | Production HTTPS examples set this to `true`. Use `false` only for HTTP-only trusted deployments. |

## Storage Paths

| Variable | Default | Purpose |
| --- | --- | --- |
| `DRASTIC_HOST_DB_PATH` | `/opt/drastic-server/db` | Host path for MariaDB data. |
| `DRASTIC_REST_SERVER_STORAGE_PATH` | `/opt/drastic-server/restic` | Host path for native restic repository data. |
| `DRASTIC_AGENT_HOST_DATA_PATH` | `/opt/drastic-agent/data` | Host path for persistent agent state. |
| `DRASTIC_AGENT_HOST_ROOT_PATH` | `/` | Host path mounted read-only into the agent at `/mnt/host`; override it to limit backup sources. |

The test environment uses `/opt/drastic-test/db`, `/opt/drastic-test/restic`, and host port `5051` instead of production's storage paths and port. Keep those overrides when creating a test `.env`.

## Bootstrap Account

| Variable | Purpose |
| --- | --- |
| `DRASTIC_BOOTSTRAP_ADMIN_USERNAME` | Initial admin username. |
| `DRASTIC_BOOTSTRAP_ADMIN_PASSWORD` | Initial admin password. Existing users are never changed by bootstrap. |

## Timeouts

| Variable | Purpose |
| --- | --- |
| `DRASTIC_GUNICORN_TIMEOUT` | Backend HTTP worker timeout. |
| `DRASTIC_REST_PROXY_TIMEOUT_SECONDS` | Backend-to-rest-server proxy timeout. |
| `DRASTIC_COMMAND_TIMEOUT_SECONDS` | Interactive backend-agent command timeout. |
| `DRASTIC_TASK_TIMEOUT_SECONDS` | Longer agent task timeout. |

The agent defaults to 2 workers, 8 pending jobs, 60 seconds for commands, 600 seconds for tasks, 86400 seconds for restic and 30 seconds to wait on cancellation. Override these with `DRASTIC_AGENT_MAX_WORKERS`, `DRASTIC_AGENT_MAX_PENDING`, `DRASTIC_COMMAND_TIMEOUT_SECONDS`, `DRASTIC_TASK_TIMEOUT_SECONDS`, `DRASTIC_RESTIC_TIMEOUT_SECONDS` and `DRASTIC_CANCEL_WAIT_TIMEOUT_SECONDS` when needed. Development overrides in `.env.dev.override` are passed to the Docker agent; the default `./scripts/dev.sh up` needs no override file.

## Agent Credentials

| Variable | Purpose |
| --- | --- |
| `DRASTIC_SERVER` | Server URL used by the agent. |
| `DRASTIC_USER` | User used for initial agent registration. |
| `DRASTIC_PASSWORD` | Password used for initial agent registration. |
| `DRASTIC_LOGLEVEL` | Agent log level. |

For optional Proxmox integration, configure `DRASTIC_PROXMOX_TOKEN_ID` and `DRASTIC_PROXMOX_TOKEN_SECRET` on the agent. `DRASTIC_PROXMOX_API_URL` defaults to `https://127.0.0.1:8006/api2/json`; `DRASTIC_PROXMOX_VERIFY_TLS` defaults to `false`. Set `DRASTIC_PROXMOX_NODE` only when automatic node detection is insufficient.

## Secret Handling

`DRASTIC_APP_MASTER_SECRET` derives the backend settings-encryption key used for repository environment values and notification URLs. Repository passwords are wrapped with a per-user recovery key that is decrypted during login and kept only in browser memory. Database data plus `.env` is not enough to open repositories without a user password or an already provisioned agent.

Agents generate their own keypair during registration. The backend stores agent-specific envelopes for local restic access keys and recovery access, but cannot decrypt them by itself. Agents hydrate restic access keys into memory during startup sync; restic access keys are not persisted in the agent data directory. Repository passwords can be generated automatically or set manually during repository creation, and revealing them in the UI requires re-entering the account password. Changing repository passwords after creation is not supported yet.

Agents generate SSH identities locally and advertise only their SSH public key to the backend. Install the public key shown in the agent properties dialog on SSH/SFTP repository targets. Agents manage SSH `known_hosts` locally in their data directory.

For production-style Homelab deployments, back up these items together:

- MariaDB data.
- `DRASTIC_REST_SERVER_STORAGE_PATH`.
- `.env` or the equivalent secret store containing `DRASTIC_APP_MASTER_SECRET`.
- Agent data directories containing registered agent identifiers, secrets, and keypairs.
