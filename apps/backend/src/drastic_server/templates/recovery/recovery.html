Start recovery without dRastic

The kit requires an AES-ZIP-compatible tool such as 7-Zip and the archive password saved at export time, not your account password. Run the commands from the extracted kit directory.

  1. Unpack the matching archive for your operating system/architecture and set RESTIC (shell) or $restic (PowerShell) to the executable's absolute path.
  2. Use the repository commands below to list snapshots, inspect files, then replace SNAPSHOT_ID with the chosen ID and restore to a new, empty directory. Recover each required VM/dataset component separately.

Shell: export RESTIC='/absolute/path/to/restic'
PowerShell: $restic = 'C:\path\to\restic.exe'

Check restored data before production use; failed attempts may leave partial files.

Direct access to managed rest-server storage

A native repository is an ordinary Restic directory: no running dRastic or rest-server is needed. The Compose host storage root is DRASTIC_REST_SERVER_STORAGE_PATH (default /opt/drastic-server/restic); /data is the container mount. Use your actual storage root plus the exact repository path:

Point Restic at the directory containing config, data, index, keys and snapshots, using the exported repository password. Take a consistent copy with writers/maintenance stopped. Do not run init, forget, prune or remove active locks during recovery.

What each backup format restores

Backup typeRestic output and next steps
File / TrueNASOrdinary files. TrueNAS has one snapshot per dataset and needs no NAS/API for file recovery; ZFS settings/history are not included. Source paths may include mnt/host/.
Proxmox Snapshot/TARqemu-<vmid>.tar with VM configuration and disks/disk-drive-*.raw. VM import or guest-file access needs additional tools or dRastic.
Proxmox Native/CBTManifest, VM configuration and numbered 4-MiB RAW blocks: not complete disk images or guest files. Use format-aware tools or dRastic to assemble/import disks or read guest files. The selected snapshot is complete; older snapshots and agent CBT checkpoints are not required.

VM tools are not bundled; encrypted guest filesystems need their own unlock keys. File ownership, permissions and platform-specific metadata may differ on the recovery computer.

Restore with a new dRastic installation

Add a Custom Repository with the existing location, exported password and provider environment. Local storage must be mounted on the recovery agent, including any container mounts. A new Native Repository would allocate a new path. Assign/synchronize it to the agent, open Actions → Restore backup and enable Show all restore points. Old jobs/reports are unnecessary; recognized Proxmox backups retain specialized restore modes when the agent has their required tools.

A new account's owner UUID does not prevent restores; old owner-tagged backups remain outside its automatic retention. This kit is not an automatic configuration import.
